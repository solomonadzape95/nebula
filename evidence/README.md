# Testnet traction — exported record

Generated by `cd indexer && npm run export`. Every file here is a mechanical rendering of the
indexer's Postgres, which itself contains nothing but decoded Soroban events read from the vault
contract. No figure in these files is entered by hand, and there is no code path that can add a row
the chain did not produce.

Regenerate before submitting: the files are overwritten in place, so what is committed is a snapshot
of whenever `export` last ran, and `summary.csv` carries `exported_at_utc` to say when that was.

## Files

| File | One row per | Notes |
|---|---|---|
| `summary.csv` | metric | Headline traction, recomputed from the rows in the other files |
| `depositors.csv` | wallet that has deposited | The Level 4 "10+ real users" evidence |
| `transactions.csv` | deposit or withdrawal | The underlying ledger record, unaggregated |
| `harvests.csv` | harvest | Realized yield and the fee taken from it |
| `share-price.csv` | priced event | The share-price and TVL series behind the chart |
| `strategy-flows.csv` | strategy | Capital allocated to and unwound from each venue |

## How to check it

Every activity row carries its own transaction hash and a Stellar Expert URL. Pick any line in
`depositors.csv` or `transactions.csv`, open the link, and the amount, the account and the timestamp
are all visible on a ledger this project does not control. The totals in `summary.csv` are sums of
those same rows, so verifying a sample of lines verifies the totals.

The vault contract the events were read from is in `summary.csv` as `vault_contract`, and the
indexer accepts events from that address only.

## What this cannot show

An on-chain record proves a transaction happened. It cannot prove that the person behind an address
is a different person from the one behind the address above it — an address is free to create, and a
funded testnet wallet costs nothing.

Two things in these files bear on that, and both are reported rather than filtered:

- **`days_active`** in `depositors.csv` counts the distinct UTC days an address transacted on. A
  batch of wallets driven from one script in one sitting all read `1`. Someone who deposited, left,
  and came back to see whether the share price had moved reads `2` or more. `summary.csv` carries
  the count as `depositors_active_on_more_than_one_day`.
- **Timestamps are exact.** Addresses appearing minutes apart in a contiguous run look like what
  they are.

So the export is deliberately not the whole argument. Identity is the half a ledger cannot carry,
and [`../docs/USER_SURVEY.md`](../docs/USER_SURVEY.md) is the other half: it collects a wallet
address alongside a person, which makes each survey response joinable to a row in
`depositors.csv` — and makes a response that claims a deposit which never happened visible
immediately.
